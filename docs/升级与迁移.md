# 升级与迁移

## 与旧 PHP 版的关系

> [!IMPORTANT]
> V3.0（Go-only）**不迁移、不读取、亦不兼容**旧版 ThinkPHP 服务端的数据结构。从 PHP 版迁移等同于全新部署：新建空库后执行 `./vmqfox-api -init-admin`（自动建表并初始化管理员，无需导入 `database/schema.sql`），再重新配置通讯密钥。

## 公开订单令牌迁移（Go-only 旧库升级必做）

新版本以 **64 位小写十六进制 `publicToken`** 作为匿名收银台凭据，并**立即停用旧 `orderId` 公开链接**。

> [!WARNING]
> 先在维护窗口运行迁移并确认成功，再同时发布后端与前端。旧订单号支付链接会失效，不能作为新版本的兼容入口。

### 命令

```bash
# 已构建二进制：读取 .env 后执行可重复（幂等）迁移
./vmqfox-api -migrate-public-tokens

# Docker Compose：保持 MySQL 已启动，但在新 API 对外启动前运行一次性迁移容器
docker compose up -d mysql
docker compose run --rm --no-deps vmqfox-api /usr/local/bin/vmqfox-api -migrate-public-tokens
```

迁移会安全地：添加 `orders.public_token` 列 → 分批回填随机令牌 → 创建唯一索引 → 设置非空约束。重复执行不会改写已有效的令牌。

### 迁移后核验

```sql
-- 全部应为非空、唯一的 64 位小写十六进制值
SELECT COUNT(*) total,
       SUM(public_token REGEXP '^[0-9a-f]{64}$') ok,
       COUNT(DISTINCT public_token) uniq
FROM orders;
```

`total = ok = uniq` 即通过，随后再启动/更新 API 与前端服务。

## 版本升级通用步骤

1. 备份数据库：`mysqldump ... > backup-$(date +%F).sql`。
2. 拉取新版本 / 替换二进制（或 `docker compose pull && docker compose up -d`）。
3. 比对 `.env` 与新版 `env.production.example`，补齐新增变量（如 V3.0 新增的 `VMQ_SERVER_*_TIMEOUT` 系列）。
4. 涉及数据库结构变更时执行对应迁移命令（如上面的令牌迁移）。
5. 校验 `/health`、`/ready`，登录管理台确认监控端在线状态正常。
